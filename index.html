Core Concepts

六大核心能力

这是 LoopForge 的主要学习内容。理解每一块的定位与协作关系，就掌握了整个平台的工作骨架。

工作区 Workspace

会话绑定的沙箱环境，用原生文件、补丁和命令工具完成任务。按需切换运行环境，自行克隆仓库、建分支、跑测试。

沙箱环境原生命令Git 自管理

SOP 工作流

把一条需求从定型到交付串成可编排的节点链路：设计、实现、评审、测试、审批、MR 各司其职，过程与产物全程可追溯。

节点编排人工审批产物归档

角色与子 Agent

评审、测试等角色可作为独立子 Agent 并行复核。高风险改动交给对应角色把关，让「做的人」和「查的人」相互独立。

独立评审并行协作交叉验证

技能 Skills

任务与某个技能描述匹配时即加载它，按说明执行即可。技能把专项能力打包复用，无需重复造轮子，加载也不需额外确认。

按需加载能力复用开箱即用

需求管理 Issues

需求从 backlog 走到完成的全生命周期管理。关联仓库、绑定 SOP、派发运行、跟踪 MR 与合入状态，一切围绕需求展开。

Git 与 MR 交付

克隆、建分支、提交、推送、开 MR 一条龙。个人凭证已配置好，开好的 MR 会自动登记到需求并跟踪合入，无需手动回填。

分支管理自动登记 MR合入跟踪

How To Work

四种工作方式，怎么选

面对一个任务，先判断该自己做、用技能、派角色，还是交给 SOP。选对方式，效率和质量都事半功倍。

A

自己做

问答、解释、只读查询和小范围改动默认自己做；用户说「直接改」「你来做」时也自己完成。

B

用技能

任务与某个技能的描述对得上时，先加载技能再照它说明执行，把专业能力直接复用起来。

C

派角色

独立评审、整套测试等本职整件事，或高风险改动需要复核时，交给对应子 Agent 独立把关。

D

走 SOP

要落到仓库的新需求或新功能，交给用途对得上的交付 SOP，从需求定型一路推进到交付。

Quick Start

四步开始你的第一次交付

从建分支到开 MR，熟悉这套节奏，就能复用在每一个需求上。

打开工作区

进入会话绑定的沙箱环境，准备好运行所需的语言与工具链。

克隆并建分支

git clone 目标仓库，切出自己的功能分支，与主干隔离开发。

改动并验证

按仓库指令开发与测试，提交 commit，确保改动经过验证。

推送并开 MR

push 分支、发起 MR，平台自动登记到需求并跟踪合入状态。
